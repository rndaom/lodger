# Research for the open-source release (2026-10-28)

Three web research passes, done before turning lodger from a tool for one PC into one anybody on Linux
can install. Facts marked *(unverified)* came from secondary sources or memory. Sources are linked inline.

## 1. Is lodger new? (other tools)

| Tool | Sizes to free memory | Steps aside for other apps | Unloads when idle | Many models | License |
|---|---|---|---|---|---|
| llama.cpp (upstream) | yes, `--fit` (on by default, 1 GiB margin), at load only | no | `--sleep-idle-seconds` | router mode, `--models-memory-margin` | MIT |
| Ollama | yes, at load | no ([request #17298](https://github.com/ollama/ollama/issues/17298), unanswered) | 5 min | yes | MIT |
| LM Studio | load-time "guardrails" | no | JIT TTL | yes | proprietary |
| Jan | ? | no | no | yes | Apache-2.0 |
| llama-swap | no (you set flags) | no | `ttl` | yes | MIT |
| LocalAI | fixed VRAM cap | no | idle watchdog | yes | MIT |
| koboldcpp | autofit estimate | no | ? | ? | AGPL-3.0 |

Tools that yield to games all match **process names** (Steam `reaper`, Wine, Proton, launcher folders) and
**unload or kill** the answer: [gpu-game-guard](https://github.com/ngillmore/gpu-game-guard),
[ollama-yield](https://github.com/preston-bernstein/ollama-yield), [VramBouncer](https://github.com/lojekq/VramBouncer)
(Windows), [GamePause](https://github.com/Vkuparin/gamepause-for-local-ai) (Windows). All tiny (0-25 stars).
None reads per-app GPU use from fdinfo, none continues a half-written answer on the processor.

**What's lodger's own:** the combination. Watching what every app really uses (no name lists), moving the model
mid-answer without losing the answer, growing back, the memory fence, refusing instead of guessing.
**Not lodger's own any more:** auto-fit, multi-model switching, idle unload (llama.cpp has all three now).
Lodger should use llama.cpp as the engine and add what it lacks, and say so.

- **Ollama API**: Raycast (free tier) and Home Assistant's Ollama integration speak only Ollama's API. A thin
  optional shim (`/api/tags`, `/api/chat`, `/api/generate`, `/api/show`, `/api/version`, `/api/ps`) is worth it;
  LocalAI and koboldcpp already have one.
- **Name**: no `lodger` on PyPI or the AUR; ~150 small GitHub repos, none about AI. npm has `@lodger/sdk`
  (an unrelated audit product). Low clash risk; trademark not checked.
- **Security**: Ollama had [CVE-2024-28224](https://www.nccgroup.com/research/technical-advisory-ollama-dns-rebinding-attack-cve-2024-28224/)
  (DNS rebinding: any web page could use it). llama-server's CORS defaults to `*`. Lodger checks neither Host nor
  Origin today. Needed: Host allowlist (localhost, 127.0.0.1, [::1]), reject foreign Origins, optional API key,
  the engine on a private port with its own key, pinned llama.cpp versions (CVE-2026-43632 is a use-after-free
  with `--sleep-idle-seconds`).

## 2. Who uses Linux, and on what

Steam survey, Linux only, September 2026 ([survey](https://store.steampowered.com/hwsurvey/Steam-Hardware-Software-Survey-Welcome-to-Steam?platform=linux)):
- Graphics memory: 8 GB 19.9%, 16 GB 18.7%, 12 GB 9.5%, 6 GB 5.1%, 4 GB 6.4%, 24 GB 3.7%; the 1 GB / 512 MB
  rows (~26%) are mostly APUs and Steam Decks.
- RAM: 16 GB 40.9%, 32 GB 32.4%, 8 GB 6.1%, 64 GB 5.2%.
- CPUs 66% AMD. Steam Deck ~16-27% of Linux users. Top distros: CachyOS, SteamOS, Arch, Mint, Bazzite.
- GamingOnLinux reader survey (self-selected): AMD 57%, NVIDIA 41%, Intel 3%; 97% of NVIDIA users on the
  proprietary driver.

**Typical machine:** AMD (Radeon or an APU, Vulkan/RADV), 8 GB card or shared-memory APU, 16 GB RAM, often a
laptop. Next: NVIDIA 8-12 GB. **Minimum worth supporting:** 6-8 GB card or APU + 16 GB RAM. Floor: 8 GB RAM,
processor only, 1-4B model.

**Models** (Apache-2.0, so fine to recommend; lodger downloads from Hugging Face at the user's request, never
redistributes): Qwen3.6-35B-A3B with experts in RAM (XDA measured up to ~33 words/s on an 8 GB RTX 3070
laptop), gpt-oss-20b (plus its usage policy), Gemma 4 26B-A4B / E4B / E2B, Qwen3.5-9B / 4B / 2B.
Avoid Llama as a default (its license needs "Built with Llama" and more). Show license name and link before download.

## 3. Graphics cards on Linux, per vendor

- **One parser for all**: the kernel's [DRM fdinfo spec](https://docs.kernel.org/gpu/drm-usage-stats.html)
  covers amdgpu, i915, xe, msm, panthor. Split on the first `:`, handle units, busy time comes as `drm-engine-*` ns
  (amdgpu, i915) or `drm-cycles-*`/`drm-total-cycles-*` (xe). Each driver only needs a table: which engines are
  3D/compute, which memory regions are on the card vs system RAM.
  - Small bug today: older amdgpu kernels print `drm-memory-gtt: \t` (space before tab); `sysmem.gpu_clients`
    splits on `":\t"` and would read 0 there. This PC's kernel (7.2) uses `drm-resident-*` without the space,
    so it's not hit here.
- **NVIDIA**: no fdinfo from its driver (nor nouveau). Use NVML through ctypes (`libnvidia-ml.so.1`): memory
  info, per-process memory (`...RunningProcesses_v3`), per-process utilization samples. Cheap check without
  NVML: `/proc/*/fd` links to `/dev/nvidia*`. NVML wakes a sleeping laptop GPU: only call it when awake.
- **Intel**: xe/i915 fdinfo as above. Arc total/free only by ioctl (`DRM_XE_DEVICE_QUERY_MEM_REGIONS`; i915 needs
  CAP_PERFMON for free). iGPUs use system RAM.
- **APUs / shared memory**: `mem_info_vram_total` is only the BIOS carve-out; the real pool is GTT = RAM.
  Budget there = min(MemAvailable − reserve, GTT limit − GTT used). Watch neighbors' `gtt`/`system` regions.
- **Hybrid laptops**: safe reads that don't wake the big GPU: `/sys/bus/pci/devices/*/power/runtime_status`,
  `mem_info_vram_*`, fdinfo. Wakes it: opening `/dev/dri/*`, `lspci -vv`, amdgpu hwmon, NVML/nvidia-smi,
  `llama-server --list-devices`, Vulkan with the NVIDIA ICD. Battery/AC: `/sys/class/power_supply/*` (skip
  `scope=Device`). Don't start work on the big GPU while on battery.
- **llama.cpp stock builds**: Linux release tarballs for CPU, Vulkan, CUDA 12.8/13.4, ROCm 10.0, SYCL, OpenVINO.
  All include `llama-server` **and** `llama-fit-params`. Vulkan needs only the loader + driver; ROCm needs a
  matching ROCm install and officially supports only RX 7700-7900 / 9060-9070. Vulkan is the safe default
  (often faster writing, ROCm faster reading); CUDA on NVIDIA. Device names `Vulkan0`/`CUDA0`/`ROCm0`; pick
  by PCI id from llama-server's `using device ... (0000:03:00.0)` log line, never by index. `--fit-print` lines
  start with the device name (plan.py's hardcoded `"ROCm0 "` must go).
- **Without systemd** (low single-digit %): a writable delegated cgroup2 if there is one, else no hard fence:
  the watchdog + `oom_score_adj=1000` (+ maybe `RLIMIT_DATA`). Never `RLIMIT_AS` (breaks mmap and GPU runtimes).
  cgroup v2's new `dmem` controller (per-device VRAM limits, amdgpu supports it) may later be a real VRAM fence.

Proposed shape (`lodger/gpu/<vendor>.py`): `devices()` (sysfs only, never wakes), `power(dev)`,
`memory(dev)` (None while asleep), `clients(pid)`, `llama_device(dev, backend)`, `launch_env(dev, backend)`,
plus engine/region tables for the shared fdinfo parser.

## 4. Shipping it

- **Primary**: PyPI, installed with `uv tool install lodger` or `pipx install lodger` (no root; uv brings its
  own Python 3.11+). `lodger setup` writes a systemd **user** unit and downloads the right llama.cpp tarball
  (Vulkan/CUDA/ROCm/CPU) with a checksum into `~/.local/share/lodger`.
- **Second**: AUR (CachyOS and Arch lead the Steam Linux distros).
- **Not Flatpak**: its private `/proc` hides other apps' fdinfo and it can't use `systemd-run`, which is the
  core of lodger.
- Comparable: Ollama (curl|sh as root, system user), Jan and LM Studio (AppImage with bundled engines),
  llama-swap (bring your own llama-server).
- **Day-one repo**: README (what, supported hardware table, 3-command quickstart, safety note, how to add a GPU),
  LICENSE (MIT), CONTRIBUTING, CODE_OF_CONDUCT, SECURITY.md, issue forms incl. a **hardware report** asking for
  `lodger doctor` output, PR template, CHANGELOG + SemVer, GitHub Actions (Python 3.11-3.13, ruff, pytest with
  recorded `/sys` and fdinfo files and a fake `llama-server`; no GPU needed).

## 5. The Sybil registry as a model source

[local-ai-registry](https://local.sybilsolutions.ai) (MIT, 0xSero) has 70 cards (incl. 8 GB NVIDIA and AMD
cards, APUs, Apple) and 370 tested recipes, a public `catalog.json` and a one-file Python client. Each recipe pins
the weights (Hugging Face repo + revision) and records measured speed on that card.
Useful to lodger for: *which models are good and exactly which file to download*. Not useful for: *how to run
it* (recipes assume the model owns the whole card, run in containers and must reach 15 words/s; lodger plans
its own placement from what's free right now). It's another project's service, so lodger shouldn't depend on it.
